# SmartKitap: подготовка к DevOps

Исходная версия `origin/main`: `3ba865a46ac132a26603d919f86b35cb111c7f76`. Работа выполнена в отдельном worktree и ветке; данные исходной рабочей папки не изменялись.

## Изменения

- Секрет обязателен в окружении; добавлены разбор настроек, пути данных и `STATIC_ROOT`. Локальный HTTP остаётся доступен; HTTPS включается явно. Заголовки прокси не считаются доверенными автоматически.
- CSV: поля с управляющими символами и формульными префиксами получают начальный апостроф. Синтаксис CSV обрабатывает `csv.writer`, BOM записывается один раз. См. ограничения импорта и повторного сохранения в README.
- Range: некорректные, слишком длинные и множественные диапазоны игнорируются и дают полный ответ; допустимый, но неудовлетворимый диапазон даёт 416. Числа ограничены 20 цифрами; системный лимит преобразования не меняется.
- Основные тесты старых PDF используют временный искусственный файл. Оба браузерных сценария используют временные базы и каталоги файлов, тестовые обложки создаются при запуске.
- Рабочие данные, бэкапы и генерируемые артефакты исключены из индекса Git с сохранением файлов на диске. Удаление из текущего дерева Git не удаляет их из истории: ранее отслеженный PDF, архивы и секрет в старом коммите остаются в истории. При использовании старого секрета необходима его замена; очистка истории и доступов не проводилась.

## Проверки

Исходная версия: `check` — 0 проблем, `makemigrations --check --dry-run` — нет изменений, `test --noinput` — 121 тест, 103 прошли, 18 пропущены из-за отсутствующего реального PDF. Исходный `check --deploy` — 7 предупреждений. Исходный прогон использовал установленный Python 3.13.14 и Django 6.0.4; тестовая БД Django была отдельной, но начальный прогон не был в отдельном виртуальном окружении.

Итоговые проверки выполнялись в свежем `.venv`, зависимости установлены из файлов требований, использован случайный ключ и отдельный путь SQLite. Браузерные сценарии запускают собственные временные БД и файлы. Точный результат последнего полного прогона приведён ниже.

- `python manage.py check` — 0 проблем.
- `python manage.py makemigrations --check --dry-run` — изменений нет.
- `python manage.py test --noinput` — 124 теста: 124 прошли, 0 пропущены, 0 ошибок и падений.
- `python manage.py collectstatic --noinput` — успешно, `staticfiles/`.
- `DEBUG=false`, `HTTPS_ENABLED=true`, случайный ключ, локальные разрешённые хосты: `python manage.py check --deploy` — 0 предупреждений. Это проверка настроек, а не проверка реального TLS, прокси или безопасности развёртывания.
- `python scripts/browser_smoke.py` — 9 сценариев прошли, ошибок JavaScript нет.
- `python scripts/ui_smoke.py` — не прошёл: при ширине 390 px после открытия боковой панели и `Shift+Tab` фокус оказывается вне `#app-sidebar`, строка проверки в скрипте рядом с `page.keyboard.press('Shift+Tab')`. Остальная часть этого сценария после ошибки не выполнялась. Проверку не ослабляли. Возможная проблема доступности требует отдельного исправления.

## Как проверить Гани

Открыть отдельную ветку, следовать README для Windows или Linux, задать собственный секрет и выполнить перечисленные проверки. Данные и файлы из рабочей установки не копировать в Git. Посмотреть `artifacts/browser-qa/` и `artifacts/ui-qa/`: файлы создаются локально при запуске и в репозиторий не входят. Сравнить работу каталога и кабинетов на русском и казахском языках. Для существующих книг при проверке использовать копии данных в отдельной директории.
